# TasbihKu Agent Instructions

Standing repository rules for all AI coding agents operating in TasbihKu. Rules are static-first to preserve prompt prefix caching.

---

## 1. JIT Context & Progressive Loading (`Read when:`)
- Read [CODEMAP.md](CODEMAP.md) first for feature domains, slots, and commands (auto-generated by `npm run codemap`; never hand-edit).
- Read [.agents/PROJECT_MAP.md](.agents/PROJECT_MAP.md) for shell, shared, styles, tooling, and test entry points.
- Read [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) when modifying cross-feature bus contracts, CSS layers, or storage architecture.
- Read [.agents/rules/context-optimization.md](.agents/rules/context-optimization.md) before multi-step work or compaction for KV-cache, handoff, offloading, and token-lean rules.
- Read [.agents/agent-progress.md](.agents/agent-progress.md) `## STATE` on session start, pre-compaction, or post-compaction recovery.

## 2. Verified Commands (Run from Repo Root)
```bash
npm run dev       # Start Vite dev server on http://localhost:3005 (strictPort)
npm run check     # Enforce <=200L/file, <=60L 0-import contracts, <=150L i18n parity, CODEMAP sync, zero globals/raw localStorage
npm run codemap   # Regenerate CODEMAP.md from src/features/*/*.contract.js headers
npm test          # Run Vitest unit & feature suites (vitest run src/ tests/unit/ --pool=forks)
npm run build     # Build dist/ and inject generated dist/assets/*.js|css into dist/sw.js
npm run size      # Verify dist/ gzip budgets (size.config.json: <=20KB shell JS, <=90KB shell CSS, <=40KB lazy chunks)
npm run test:e2e  # Run Playwright E2E tests (requires Chromium; see .agents/agent-progress.md for open E2E probes)
```
- Targeted checks: `npm run check -- --shell`, `--i18n`, `--css`, `--feature <name>`, `--size`.

## 3. Architecture & Code Constraints
- **Zero-framework vanilla ES Modules:** Do not introduce runtime frameworks (React, Vue, Preact) or CSS preprocessors/utility frameworks (Tailwind, Sass).
- **Hybrid Feature-Sliced layout:** Thin shell (`src/main.js`, `src/app/`, `src/shared/`, `src/styles/`) + depth-1 flat feature folders (`src/features/<name>/`).
- **Structural gates (`scripts/check.mjs`):**
  - `.js` and `.css` files under `src/` must stay `<=200L`; `*.contract.js` `<=60L` with zero imports; `*.i18n.json` `<=150L` with `id`/`en` key parity.
  - Zero `index.js` barrels, zero cross-feature non-contract imports, zero `window.<fn> = ...` assignments, zero inline `on*=`/`<style>` in `index.html`, and zero direct `localStorage` access outside `src/shared/storage.js`.
  - Feature CSS must wrap rules in `@layer features`; design tokens live in `src/styles/tokens.css` (imported via `style.css`).
- **Windows junction safety:** `vite.config.js` resolves `fs.realpathSync(process.cwd())`; preserve this for `C:\AnimatorBP` NTFS junction compatibility.

## 4. Mandatory Version Bumping & Changelog Standards
For **every non-trivial update, feature addition, bug fix, or refactor**:
1. Run the automated version bumper rather than editing version strings manually:
   ```bash
   node scripts/bump-version.js patch "Brief summary of changes"
   ```
   - Use `patch` for bug fixes, cleanup, or minor adjustments; `minor` for new features/architectural updates; `major` for breaking changes.
2. Version format is `tasbihku-vX.Y.Z`, with `"version"` in [package.json](package.json) as the single source of truth (synced to `src/app/version.js`, `public/sw.js`, and [CHANGELOG.md](CHANGELOG.md)).
3. Enrich the generated entry in [CHANGELOG.md](CHANGELOG.md) following Keep a Changelog with structured breakdowns (UI/Component Changes, Core Logic/Workflows, Dzikir & Habits Engine or Architecture/Tooling, and Test & Verification commands/results).
